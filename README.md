# LASA Medicine Selection Safety Interface

A field-ready prototype tackling **look-alike / sound-alike (LASA) medicine selection risk**
in a hospital pharmacy serving wards, operating rooms and outpatients.

This repository contains a working end-to-end prototype (not a slide deck or notebook):
a baseline model of the current process, a proposed safety-aware selection engine, an
interactive browser demo with original packaging artwork and simulated shelf/barcode
checks, a reproducible controlled-dispensing experiment comparing the two, unit tests
covering realistic failure states, and the supporting documentation set.

## Why this problem matters

LASA errors happen because pharmacy staff, nurses and anaesthetists select medicines
under time pressure from alphabetised lists and visually similar packaging, using
partial names heard verbally or typed quickly. See
[`docs/problem_investigation.md`](docs/problem_investigation.md) for the full analysis
of why this creates selection risk specifically in a ward / OR / outpatient pharmacy.

## Quick start

```bash
# 1. Run the test suite (pure standard library, no install required beyond pytest)
pip install pytest --break-system-packages     # or: pip install -r requirements.txt
python3 -m pytest -q

# 2. Reproduce the controlled dispensing experiment
python3 -m src.simulate_dispensing
# writes results/experiment_results.json, results/error_analysis.csv,
# results/trial_log.csv, results/comparison_chart.svg

# 3. Open the interactive prototype - no server or build step needed
open web/index.html        # macOS
# or just double-click web/index.html in a file browser
```

If you change `data/medicines.csv`, regenerate the original packaging artwork and the
bundled web data with:
```bash
python3 tools/generate_packaging.py
python3 - <<'PY'
import csv, json
meds = list(csv.DictReader(open("data/medicines.csv")))
pairs = list(csv.DictReader(open("data/lasa_pairs.csv")))
packaging = {m["id"]: open(f"data/packaging/{m['packaging_file']}").read() for m in meds}
with open("web/data.js", "w") as f:
    f.write("window.LASA_DATA = "); json.dump({"medicines": meds, "pairs": pairs, "packaging": packaging}, f); f.write(";")
PY
```

## What "baseline" and "proposed" mean here

- **Baseline** (`src/baseline.py`) models the current-state process: a plain substring
  search over an alphabetised list, auto-highlighting the first match, with no
  confidence score, no risk flag, and no mandatory verification. This is deliberately
  simple - it is what a large share of legacy pharmacy/EHR pick-lists actually do.
- **Proposed** (`src/safety_engine.py`) attaches an explicit, visible risk assessment to
  every candidate: a confidence score, the identity of anything it could be confused
  with and why, tall-man lettering, and risk-proportionate friction (mandatory
  independent second check and barcode confirmation for High/Critical risk items,
  forced disambiguation for ambiguous ties).

Both are exercised by the exact same interactive prototype (toggle at the top of
`web/index.html`) and by the exact same controlled experiment
(`src/simulate_dispensing.py`), so the comparison is apples-to-apples.
