# Data schema

## `data/medicines.csv`

| Field | Type | Description |
|---|---|---|
| `id` | string | Stable identifier (`M01`...`M18`), also used as the simulated barcode payload. |
| `name` | string | Display name as commonly written. |
| `tallman` | string | Tall-man lettering form used in the proposed interface's candidate header (e.g. `hydrALAZINE`). |
| `generic` | string | Full generic/salt name, used as a second similarity signal. |
| `strength` | string | Dose/concentration as dispensed. |
| `form` | string | tablet / capsule / vial / ampoule / pen. |
| `route` | string | oral / IV / IM-IV / SC. |
| `shelf_location` | string | Simulated shelf/bin code, format `AREA-BAY-POSITION`. |
| `ward_area` | string | Ward / Operating Room / Oncology / Outpatient. |
| `packaging_file` | string | Filename of the original SVG artwork in `data/packaging/`. |
| `harm_if_confused` | string | Plain-language description of the clinical consequence if this item is dispensed by mistake for its confusable partner(s). Rendered directly in the risk banner - this is the "potential harm from incorrect recommendations" requirement made concrete per item, rather than a generic warning. |

## `data/lasa_pairs.csv`

| Field | Type | Description |
|---|---|---|
| `id_a`, `id_b` | string | The two confusable medicine IDs (order is not significant). |
| `confusion_type` | string | `sound-alike`, `look-alike`, or `sound-alike+look-alike`. |
| `reference_risk_tier` | string | `Low` / `Medium` / `High` / `Critical` - the curated ceiling for this pair, drawn from the pair's clinical stakes (e.g. Critical for anything with a narrow therapeutic index or opposite intended effect). |
| `notes` | string | Short rationale, matching the kind of note a pharmacy safety committee would record. |

Curated pairs are looked up directly by ID in `safety_engine.py` (`known_pair_lookup`),
independent of the live similarity score - see `docs/error_analysis.md` for why both
signals are needed together.

```json
  "proposed_error_rate": 0.1013,

  "measured_percent_reduction": 0.7492,
  "target_met": false,
  "control_trials": 80,
  "control_false_positive_flags": 0,
  "control_false_positive_rate": 0.0,
  "pair_breakdown": { "...": "per-pair trial counts and error counts" }
}
```

`results/error_analysis.csv` - one row per LASA pair with trial counts, error counts
and rates for both engines, plus errors prevented.

`results/trial_log.csv` - one row per simulated trial: the corrupted input, the
intended medicine, whether baseline erred, whether the proposed engine flagged it, and
whether the proposed engine still erred. This is the raw evidence behind the summary
numbers.

## Web bundle (`web/data.js`)

Generated (not hand-edited) by bundling `medicines.csv`, `lasa_pairs.csv` and every
SVG under `data/packaging/` into a single `window.LASA_DATA` object so the prototype
runs from a plain file:// open with no server or build step. Regeneration command is
in the root `README.md`.
