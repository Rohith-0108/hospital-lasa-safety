# Risk register

Severity/Likelihood are qualitative (Low/Medium/High) for this prototype stage.

| # | Risk | Severity | Likelihood | Mitigation in this prototype | Residual risk / follow-up |
|---|---|---|---|---|---|
| R1 | Wrong medicine dispensed due to name confusion | Critical | Was High (baseline) | Confidence score, tall-man lettering, confusable-neighbour display, mandatory second check for High/Critical risk | Not fully mitigated - see `docs/error_analysis.md`: measured reduction is 74.9%, below the 90% target, concentrated in the Medium-risk Metformin/Metronidazole pair which doesn't currently trigger mandatory checks. |
| R2 | Wrong medicine dispensed due to packaging/shelf confusion (name was typed correctly) | Critical | Medium | Barcode scan + shelf-location check, independent of name-matching logic | Barcode/shelf checks assume scanning hardware works; scanner-offline fallback is modelled (failure case 3 in `docs/error_analysis.md`) but not hardware-tested. |
| R3 | Alert fatigue from over-flagging safe, unambiguous picks | Medium | Low (measured 0.0% false-positive rate on control items in current run) | Risk-proportionate friction: Low-risk picks have zero extra steps | Needs re-validation as the medicine catalogue grows past 18 items; current 0% is on a small, curated set. |
| R4 | Staff bypass mandatory checks under time pressure (esp. OR STAT scenarios) | High | Medium-High (structural - OR time pressure is real and legitimate) | Override path exists but requires a typed reason and is permanently logged for supervisor review; never silent | Override still allows dispensing to proceed - this is a deliberate design trade-off (clinical urgency must not be blocked outright) documented, not hidden. Needs supervisor-review workflow beyond this prototype's scope. |
| R5 | Curated LASA pair list becomes stale as formulary changes | Medium | Medium | Live similarity detection (`SIMILARITY_ALERT_THRESHOLD`) catches *new* confusions even if not yet added to the curated list | Curated list still needs a governance owner and review cadence (pharmacy safety committee) - process, not code. |
| R6 | Similarity algorithm misses a real confusion pair that scores low on Levenshtein+Soundex (e.g. Losartan/Lorazepam) | High | Confirmed present (see `tests/test_similarity.py::test_combined_similarity_alone_does_not_catch_every_known_pair`) | Curated pair list is consulted independently of the live score, specifically to cover this gap | A future ML-based visual/phonetic model (see `docs/error_analysis.md` future work) could reduce reliance on manual curation. |
| R7 | Second-check catch-rate (88%) is a modelling assumption, not measured local data | Medium | N/A (methodological risk) | Explicitly documented as an assumption in `docs/stakeholder_assumptions.md`, not presented as fact | Must be replaced with site-specific data (e.g. from a pilot period audit) before the 90% target claim is used operationally. |
| R8 | Prototype packaging artwork does not match real manufacturer packaging | Low (for the prototype's purpose) | N/A | Artwork is intentionally schematic/generic - see `docs/architecture.md` for why the interface targets name+barcode+shelf rather than visual packaging recognition | A production system integrating photographs of actual stock would need its own image-similarity validation. |
| R9 | Demo/prototype code path confused with a production system | Medium | Low | Footer disclaimer in `web/index.html`; README states "not connected to a live pharmacy system" | N/A for prototype phase. |
